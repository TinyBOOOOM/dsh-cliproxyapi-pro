# AGENTS.md — working on dsh-cliproxyapi-pro

Guide for coding agents (and humans) changing this repository. Read it before editing; keep it current when the architecture changes.

## What this is

A [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) (DSH) bundle that connects one or more [CLIProxyAPI](https://github.com/router-for-me/CLIProxyAPI) (CPA) servers, discovers their model catalogs, and writes the selected models as provider routes into the `llm-pi-ai` settings namespace so they appear in the DSH model picker. It ships:

| Surface | Where |
|---|---|
| Host plugin (Cordis, ESM) | `lib/index.js` — exports `name`, `inject`, `apply` |
| Web UI client module | `lib/client.js` — account/model page in the `settings.section` slot (Settings left nav, id `cliproxyapi`); update-only page in `plugins.bundle.config` and `settings.plugins.tab` |
| Offline updater (internal ESM) | `lib/updater.js` — preferences, channel/region checks, verified offline package downloads; never installs |
| Quota engine (internal ESM) | `lib/quota.js` — CPA management API (auth-files, per-credential models, upstream quota via api-call), 5-minute cache, model → credential matching; management keys only through credentials refs `CLI_PROXY_MANAGEMENT_KEY[_<ID>]` |
| Quota HTTP routes | `/api/dsh-cliproxyapi/quota/{status,refresh,save}` |
| Market installation (client) | `lib/client.js` — dshmarket Update API v1 one-click install and opt-in auto-install; the market installs |
| Bundle patch | `cordis.patch.yml` — inserts row `dsh-cliproxyapi-pro` |
| Display metadata | `locale/en.json`, `locale/zh.json` (`meta.title`, `meta.description`), `icon.svg` |
| Agent tool | **None, on purpose.** The plugin registers no `ctx.tools` entry (see the invariant below) |
| Slash commands | `/cpa-status`, `/cpa-refresh` |
| Account HTTP routes | `/api/dsh-cliproxyapi/{status,refresh,save,accounts/add,accounts/remove,accounts/test}` |
| Update HTTP routes | `/api/dsh-cliproxyapi/updates/{status,check,save,download}` |
| Tests (`node:test`) | `tests/plugin.test.mjs`, `tests/updater.test.mjs`, `tests/update-routes.test.mjs`, `tests/quota.test.mjs`, `tests/client.test.mjs` |
| User docs | `README.md` (中文, default) and `README.en.md` (English) — keep both in sync |
| CI / release | `.github/workflows/ci.yml`, `.github/workflows/release.yml` |

Repository: <https://github.com/TinyBOOOOM/dsh-cliproxyapi-pro> (default branch `main`).

## Hard constraints

- **Zero dependencies, no build.** Only Node.js built-ins and Cordis context services (`ctx.settings`, `ctx.credentials`, `ctx.commands`, `ctx.webServer`, `ctx.logger`). Do not add `dependencies`, install scripts, TypeScript, or bundlers. Installation must stay offline-safe.
- **Client module format.** `lib/client.js` is hand-written for `window.__ModuleLoader__.load({ id, factory })`; the id equals the package name. React comes from `require("react")` inside the factory. Never `require` any `@deepseek-ai/dsh-client-*` package — entries in `dsh.client.inject` only order activation.
- **Host UI conventions.** Style only with `--dsw-alias-*` theme tokens (literal colors only in artwork); to match native controls the quota UI also uses DSH design tokens (`--dsw-radius-*`, `--dsw-elevation-*`, `--dsw-menu-surface-fill` / `--dsw-menu-backdrop-filter`, `--dsw-alias-interactive-*` / `--dsw-alias-button-*`), always with a core `--dsw-alias-*` fallback, keep all visible text in the `zh`/`en` dictionaries registered through `ctx.locale`, use `role="switch"` + `aria-checked` for toggles, and render only inside the registered slots (no DOM writes outside the component, nothing appended to `document.body`).
- **Resources are effects.** Every timer, listener, registration and stylesheet is created inside `apply` and disposed via `ctx.effect` / `ctx.on`. Timers that later write settings must be created through `outsideHmrTransaction(ctx, …)`, otherwise writes fail with "HMR transactions cannot be nested". Component polling uses a cleaned-up `useEffect`, cancels requests, and never sets state after unmount.
- **Secrets.** API keys live only in the DSH credentials service (`credentials.set/resolve/unset` by ref). Never write keys to `state.json`, settings, logs, tool output, or commits. Never print a resolved key or forward credentials to update registries.
- **Updater boundary.** Current DSH rejects replacing an installed plugin while running. This plugin never runs a package manager, uninstalls, overwrites installed/source files, or restarts DSH by itself. Installation is delegated only to dshmarket's public, versioned Update API v1 (`/dsh-market/api/v1/*`, schema `dsh-market/update-api/v1`), called from the Web client with the page's session; never call the market's private `/dsh-market/*` routes or copy its installation algorithm. Without the market, the host updater checks and downloads only, and the displayed command is inert text for the user to run after closing DSH.
- **Manifest.** The DSH version range is top-level `engines.dsh` (DSH evaluates it with prereleases included). Keep `exports` (`.`, `./client`, `./locale/*.json`, `./icon`, `./cordis.patch.yml`, `./package.json`) and `files` in sync with every shipped file. `lib/updater.js` and `lib/quota.js` are internal relative imports, shipped in `files`, not public package exports.

## Architecture (lib/index.js, by `#region`)

1. **Constants & Config Resolution** — defaults, `ACCOUNT_FIELDS`, `resolveConfig()` (normalizes one account + globals; tolerant of bad input), `normalizeModelOverrides()`.
2. **Accounts** — `normalizeState()` (v1 flat file → `accounts[0]` with id `default`; dedupes ids), `mergeHostConfig()` (patch-row `config` overlay), `accountConflicts()` / `assertNoConflicts()`, `newAccountDefaults()` (`account-N`, `cli-proxy-N`, `CLI_PROXY_API_KEY_N`, disabled), `patchAccount()`.
3. **Persistent State Store** — `<profileDir>/.dsh-cliproxyapi/state.json`, atomic write via temp file + rename.
4. **Discovery & Catalog Parsing** — `discoveryCandidates()`, `discoverCpa()` (`/v1/models?client_version=pi` enriched catalog + plain `/v1/models` for `owned_by`), `parseCatalog()`.
5. **Profile & Model Builder** — filtering, family/version sorting, `nativeProtocol()`, `buildPiAiRoutes()` (one route per protocol), `managedRouteKeys()`.
6. **Runtime Synchronizer** — `CpaRuntime` (one per account: discover → build → diff-write routes → follow default model), `serializeSettings()`, `createCpaController()` (owns account runtimes and state; all account UI/command/HTTP operations go through it).
7. **HTTP Gate** — `admitRequest()` enforces host connection policy, loopback/trusted host, same-origin for POST. `admitUpdateRequest()` additionally requires a Host and, when an `Origin` is present, the same authority under the Origin's own `http(s)` scheme (the host connection fence's rule). A missing `Origin` is allowed: the DSH desktop shell (`forwardWebRequest` in the desktop main process) strips `origin`, `host` and `sec-fetch-site` before forwarding page requests with its session cookie, so requiring it rejects every desktop update POST (the 1.5.1 "check fails" bug; dshmarket hit the same, its #648).
8. **Mount Once Guard** — prevents double activation across HMR generations.
9. **Plugin Apply** — wires state file, credentials, timers, commands and HTTP routes to the controller, plus an independent updater and its disposed startup/6-hour schedule.

`lib/updater.js`: `loadUpdateSettings()` / `saveUpdateSettings()` own separate v1 preferences; `parseUpdateVersion()` / `compareUpdateVersions()` implement strict SemVer; `validateUpdateMetadata()` validates channel/package/HTTPS registry metadata; `createPluginUpdater()` owns checks, automatic region racing, candidate generations and abortable downloads; `verifyUpdatePackage()` checks registry-provided SHA-512 integrity and restricted gzip/tar structure without extraction; `storeUpdatePackage()` atomically saves the verified `.tgz`. Integrity from registry metadata is not a publisher signature or npm provenance verification.

`lib/quota.js`: `createQuotaController()` (fed by `controller.quotaAccounts()`: id, endpoint, owned `routes`, `pickerModels`) returns cached snapshots, refreshes stale accounts in the background, locks an account out of background refresh after a management 401/403 until `saveKey`/manual refresh, and never touches the management API without a key. `matchCredentials()` is the single source of model → credential mapping (`modelIndex`/`modelMatch` in each snapshot account): prefixed ids only to that prefix, bare ids prefer un-prefixed credentials, family heuristics only when model lists are missing. Snapshots never contain keys, tokens or raw upstream bodies.

Quota probes (`PROBES`, keyed by normalized provider) mirror CLIProxyAPI's management center (`src/features/quota/providers/*` in router-for-me/Cli-Proxy-API-Management-Center): codex, claude, antigravity, gemini-cli, kimi (kimi.com / kimi.ai hosts, retry the other on 401/403), xai, devin (`GetUserStatus`, account-wide daily/weekly windows without a model filter), meta. Upstream tokens normally stay inside CPA via `$TOKEN$`; the one exception is Meta, whose endpoint needs the credential's `dca_token`: `meta` reads only that field from `/v0/management/auth-files/download` for one request and must never store, log or return it. Any other credential with `supports_quota` goes through `pluginProbe` → `POST /v0/management/quota/fetch` (CPA's normalized `pluginapi.QuotaFetchResponse`, parsed by `groupedQuotaWindows()`). Never add probes that spend money (e.g. CPA's paid-xAI chat-completion health check); background refresh runs every 5 minutes. When CPA adds a quota provider, compare against the management center first.

`lib/client.js`: surfaces registered in `apply`.
- `settings.section` renders `CpaSectionPage` → `CpaSettingsPanel`: one account bar (+ `AddAccountForm`, which tests with `accounts/test` before `accounts/add`), then `AccountPanel` keyed by account id with **Connection / Models / Quota** tabs (`QuotaPanel` with `accountId`, no switcher of its own). The **Enabled** switch and **Clear Key** call `actions.patch` with one field and never bump `rev`; `actions.save` sends the full draft (without `enabled`) and bumps `rev`. Dirty state = draft vs live `account.config` + selection/overrides + key draft; one sticky save bar; account switches confirm before discarding. Secondary help text uses `InfoTip` (button + `role="tooltip"`), never `title` attributes.
- `conversation.input.right` (order 10000; the composer renders this list immediately before the model selector) renders `QuotaBadge`. Its registration `inject(sessionId)` passes a resolver for `modelDirectories.directoryFor(sessionId).store` from ui-model-selection (resolved at render, see below); the badge reads `pending ?? current` `{ provider, model }` and calls `summarizeModelQuota()`, which looks only inside the account whose `routes` contain that provider and only at `modelIndex[model]`. It renders nothing for other routes or when the account has no management key. Its peek is `position: fixed` inside the component (no portal, nothing appended to `document.body`).
- DSH renders `conversation.input.right` only when the session's input state exists (a bound session), but the New Session hero already shows the model selector. A second entry `${NS}:quota-hero` in `conversation.hero.options` renders `QuotaBadge` with `placement: "hero"`; `useBadgePlacement()` hides it while a composer badge for the same `sessionId` is mounted (in-memory `composerBadges` presence counts), so exactly one badge shows. Both entries share `injectDirectory` (`{ resolveDirectory, sessionId }`). DSH caches an entry's `inject()` result per session binding, and `directoryFor()` throws until the session has a scope/binding (page load, host restart, session switch), so inject must never resolve the directory itself (a cached miss hid the badge for good); `useDirectory()` resolves at render and retries (1 s for 30 s, then 5 s) until it exists.
- Every list/keyed slot registration goes through `registerListEntry()`: DSH rejects a duplicate id/key at the same priority, and a hot reload may overlap activations, so it retries one priority lower with the same id/key. Each activation owns its own `<style>` element. Never share DOM/registrations between activations.
- One page-wide `createQuotaStore()` (`sharedQuota`) polls `quota/status` only while subscribed (60 s; 4 s while the host reports `refreshing`) and is disposed with the activation.
- `settings.section` (id `SETTINGS_SECTION_ID` = `cliproxyapi`, like dshmarket's `market` section): `CpaSettingsPanel` owns account server data and notices; `AccountPanel` drafts reload when `rev` changes (save, discard, account switch). It contains no update UI. The section has no icon field; the shell shows its default glyph. Do not patch the nav DOM to add one (dshmarket does; it breaks the "no DOM writes outside the component" rule).
- `plugins.bundle.config` (key = package name; `view: 'summary'` renders nothing) and `settings.plugins.tab` render `PluginUpdatePage`: a short pointer to the account section plus `PluginUpdatePanel` with `initiallyOpen`. Keep account UI off these pages.

Update polling must never refetch account status or bump `rev`. `PluginUpdatePanel` renders a native `<details>`: the summary is a compact single row (title, current version, short localized status) and everything else lives in the content block. It starts closed unless `initiallyOpen`, which passes a constant `open: true` that never changes (React does not rewrite an unchanged prop, so the user can still collapse it). Never pass a changing `open` prop or remount the panel on polling/save, so the user's expanded state and the background schedule survive updates.

`lib/client.js` (dshmarket region): `createMarketUpdater()` is one page-wide client of the market Update API (capability discovery, `POST updates`, operation polling, optional restart) created in `apply` as `sharedMarket` and passed to `PluginUpdatePanel` as `market`; `startAutoInstall()` is the opt-in background runner. Both are disposed with the activation. The panel renders no market UI when `market` is null (tests/previews). New panel hooks go after the existing ones: the test harness seeds hook slots 0/1 as `update`/`loading`.

## Invariants — do not break

- An account owns exactly `managedRouteKeys(provider)` = `provider`, `provider-responses`, `provider-messages` under `llm-pi-ai.providers`. It never writes or unsets keys in `config.reservedKeys` (other accounts' keys). An account in conflict owns nothing and only reports an error.
- The base key (`provider`) always carries OpenAI Chat models so existing sessions and `agent-default-model` keep resolving; `followDefaultModel()` moves the default when protocol routing relocates its model.
- Disabled ⇒ the account's routes are removed, settings kept. Periodic refresh never probes disabled accounts; a manual refresh (`probe: true`) may, to list models.
- An explicit `baseURL` is the only candidate (`autoDiscover: false`); fallbacks (existing route URL, `CLIPROXYAPI_BASE_URL`, local `:8317`) apply only when `baseURL` is empty.
- Account ids are stable; renaming `provider` releases the old keys on the next sync. Removing an account tears down its runtime and unsets its routes but keeps its stored credential.
- Re-syncing unchanged data performs **zero** settings writes (diff via `sameJson`). User-set fields on managed routes (e.g. `retryPolicy`) survive; only `MANAGED_ROUTE_FIELDS` are replaced.
- `selectedModels` absent means "never chosen": the first successful probe seeds `recommendModels()` (newest per family, from that server's catalog) exactly once via `seedSelection`. `[]` is an explicit choice meaning "all models". Never ship hard-coded model ids as defaults — catalogs differ between servers.
- **No agent tool.** The plugin is managed through the Settings page, its HTTP routes and the slash commands only. Do not register anything with `ctx.tools` (the former `cliproxyapi` tool cost ~3K tokens of model context in every session) and do not reintroduce it behind a switch; `apply()` never injects `tools` (asserted in `tests/plugin.test.mjs`).
- `state.json` is re-read on every access so hand edits apply; always write the normalized shape (`version: 2`). Format changes need a migration in `normalizeState()` plus a test, and must keep a v1 file loading losslessly.

### Offline update invariants

- Preferences live only in `<profileDir>/.dsh-cliproxyapi/update-settings.json`: `{ version: 1, autoCheck, autoDownload, autoInstall, channel, region }` (`autoInstall` is optional within v1; older files load as `false`). Never merge them into account state or `GLOBAL_FIELDS`. A missing file uses defaults (`autoCheck: true`, `autoDownload: false`, `autoInstall: false`, `stable`, `auto`); unreadable, malformed or invalid settings disable automatic network checks. Reload re-reads preferences; check/candidate/download-notice state is not persisted.
- Automatic checks run about 3 seconds after startup or rescheduling settings, then every 6 hours. `autoDownload` acts only after an automatic check finds a newer version and requires `autoCheck`. Manual check and download remain explicit operations. GET status and UI polling never contact a registry.
- `stable` / `beta` / `dev` map to npm `latest` / `beta` / `dev`. Unpublished channels fail explicitly; never silently fall back across channels or offer a downgrade. Region `auto` races npmjs and npmmirror for the first valid metadata; `global` / `cn` use only their chosen registry. Regions affect plugin updates only, never CPA requests or other installation sources.
- Metadata requests never follow redirects. Package requests follow at most 3 individually validated HTTPS redirects; Global stays on the exact npmjs package path, and China stays on npmmirror or its official `cdn.npmmirror.com/packages/<name>/<version>/<name>-<version>.tgz` path. Never allow arbitrary hosts, credentials, ports, queries, cross-region fallbacks or HTTP downgrades; integrity always comes from the original metadata.
- Validate registry origin/path, package name/version, SHA-512 integrity and bounded gzip/tar structure. Every regular file must be declared by the package's own `package.json` `files` (`packageFilePatterns()`, npm glob semantics) or be a root file npm always packs (`ALWAYS_PACKED`); never reintroduce a hard-coded file list — it makes every future file addition break offline updates for installed versions. Fixed structural rules stay: plain ASCII path segments (no dotfiles, spaces or shell characters), at most 6 segments, no `node_modules`, no empty directories, at most 1000 entries. Reject traversal, links/special entries, dependencies and installation lifecycle scripts. Rejections carry a log-only `detail` (logged through `deps.logger`); the page shows only the localized code. Do not extract or execute the downloaded package. Never describe these checks as publisher-signature or provenance verification.
- Verified packages are atomically written under `<profileDir>/.dsh-cliproxyapi/updates/dsh-cliproxyapi-pro-<version>.tgz`; users clean up historical files themselves. Never alter installed files, profile dependency declarations, accounts or credentials while preparing a download.
- Normal installations display `dsh plugin --profile 'name' add 'absolute.tgz'` for use only with DSH closed, followed by a restart. Linked installations can check/download but return no upgrade command: keeping the link requires manually updating source; installing an offline package would change its source. Preserve this warning in both dictionaries and docs.
- Market installation: discovery reads only `GET dsh-market/api/v1/capabilities` (local, never a registry) and requires `schema`, `apiVersion: 1` and `features.update`. One-click install needs a version confirmation; `force: true` is offered only manually after `RELEASE_TOO_FRESH` / `VERSION_UNCHANGED`. Show a restart button only when `features.restart` and `restart.supported` are true; otherwise give restart/refresh hints from `outcome`. Report the version the market actually installed and warn when it is below the checked target (the market resolves with its own channel). Never offer market installation for linked installs. Localize market failure codes; never render `failure.message`.
- `autoInstall` acts only in an open Web page, only when the Host status says `autoInstall && autoCheck && available` with no `blockedReason` and a newer `latestVersion`, never forces, and tries a version at most once per 6 hours (localStorage memory; an installed version is never retried). The switch cannot be turned on while the market is not detected, but can always be turned off.
- POST responses can report an operation failure inside `update.errorCode` even with `ok: true`; check both, and localize error codes rather than exposing backend messages/stacks. Requests racing settings changes or unmount must not overwrite newer state. Dispose timers and abort in-flight work on HMR/unmount.

## Adding a setting

**Account setting:** update, in order: `ACCOUNT_FIELDS` and `resolveConfig()` → `pickAccount()` → `accountPatchFromInput()` (HTTP) → client draft state, the draft-loading `useEffect`, `onSave` payload and form control (with `zh`/`en` strings) → the API tables in **both** `README.md` and `README.en.md` → a test. Global (all-account) settings go in `GLOBAL_FIELDS` instead.

**Update preference:** change updater defaults/normalization, strict persisted-file validation and `save()` validation → the isolated update card and both locale dictionaries → both READMEs → updater/client/HTTP tests. Keep the independent preferences schema versioned; do not change account-state migration for an update preference.

## Commands

```powershell
npm test              # node --test tests/*.test.mjs
npm run check         # syntax-check index/client/updater, then all tests
npm run pack:check    # list the files a packed bundle would contain
node --test tests/updater.test.mjs tests/update-routes.test.mjs tests/client.test.mjs
```

Tests fake `fetch`, settings and credentials; they never touch the network or the real profile. Add a test for every behavior change in `CpaRuntime` / `createCpaController` (see the `multi-account` suite and its `harness()` helper). `tests/updater.test.mjs` covers preferences, SemVer/channels, metadata racing, checksum/package validation and lifecycle; `tests/update-routes.test.mjs` covers update HTTP admission/operations; `tests/client.test.mjs` uses a dependency-free VM/Hook harness for update rendering, localization, independent requests, confirmation and cleanup. For client changes, at least `node --check lib/client.js`; a quick server render with any locally available `react` + `react-dom/server` is optional (patch `React.useState` before evaluating the module, because the client destructures hooks at load time). Do not install React just for validation.

## Working against a live Harness

- This directory may be installed **by link** into the user's profile (`plugin_manager list_bundles` shows `source: link:<this dir>`). Saved edits then become live on the next plugin reload — and the agent session itself may be using models routed through this plugin. Make risky changes in a scratch copy, get tests green, then copy back only within the user's approved scope.
- Back up `<profileDir>/.dsh-cliproxyapi/state.json` before changing its format or migration logic. Update preferences intentionally do not modify that format.
- Reload host code: `plugin_manager set_plugin include:dsh-cliproxyapi-pro` `enabled:false`, then `enabled:true`. Routes already written to `llm-pi-ai` persist across the reload. Client code needs a page refresh.
- Verify account behavior through `/cpa-status` / `/cpa-refresh` or the Settings page; HTTP routes require the Web session's auth and return 401 to plain `curl`. Update POSTs additionally reject a present cross-origin `Origin`.
- Never upgrade the live plugin, uninstall it, restart DSH or overwrite a linked checkout merely to test the updater. Prefer injected offline I/O and component fixtures. Restore any account, selection or route you changed while testing.

## CI and release

- `ci.yml` runs `npm run check` and `npm pack --dry-run` on Ubuntu and Windows with Node 22 and 24 for pushes to `main` and pull requests. Keep `npm run check` green before pushing.
- `release.yml` runs on a pushed tag `v<version>`, or by hand for an existing tag (`gh workflow run release.yml -f tag=v<version>`): it fails unless the tag equals `package.json` `version`, runs the checks, creates a GitHub Release whose notes are that version's `CHANGELOG.md` section, attaches `dsh-cliproxyapi-pro-<version>.tgz` and the version-free `dsh-cliproxyapi-pro.tgz`, and runs `npm publish` through **npm trusted publishing** (OIDC, `id-token: write`; provenance is attached automatically). Each step is idempotent (an existing Release or an already-published npm version is skipped), so re-running finishes a partial release.
- Stable releases publish to npm `latest`; Beta and Dev prereleases use `beta` and `dev` and are marked as GitHub prereleases. A prerelease must never replace `latest`. Maintain the channel mapping consistently with updater dist-tags.
- **No npm token exists anywhere** — not in repository secrets, files, or chats. The npm package's Settings → Trusted publishing names GitHub user `TinyBOOOOM`, repository `dsh-cliproxyapi-pro`, workflow `release.yml`, no environment, with `npm publish` allowed; Publishing access is "Require two-factor authentication and disallow tokens". Renaming `release.yml`, moving the publish step into another workflow, or changing `repository.url` in `package.json` breaks publishing until that configuration is updated on npmjs.com. Never reintroduce an `NPM_TOKEN` secret.

## Release checklist

1. For an actual release, bump `version` in `package.json` and the pinned versions in both READMEs (`dsh-cliproxyapi-pro@<version>` and the `#v<version>` Git target); turn the `Unreleased` notes into a `## <version> — <date>` section of both `CHANGELOG.md` and `CHANGELOG.en.md` (the release workflow publishes exactly the `CHANGELOG.md` section, i.e. the Chinese notes, as the Release notes).
2. `npm run check` passes; `npm run pack:check` lists exactly `lib/index.js`, `lib/client.js`, `lib/updater.js`, `lib/quota.js`, `locale/*.json`, `cordis.patch.yml`, `icon.svg`, `README.md`, `README.en.md`, `CHANGELOG.md`, `LICENSE`, `package.json`.
